Sometimes one recording needs several scripts: a Saudi and an Egyptian version, English and Arabic, a short and a long wording. A variant is a small file that rewrites the narration (and the voice) of a storyboard without touching anything else. This page also covers slot-fit, which tells you when a line is too long for the time it has. For another look (colours, fonts) instead of another script, see Variants: the same video with another look.

The variant file

Put variants/<name>.json next to the storyboard:

{
  "voice": { "name": "ar-SA-HamedNeural" },
  "narration": { "open": "هلا، نفتح الإعدادات.", "save": "ونحفظ." },
  "overlays": { "0": { "src": "assets/logo-sa.png" } }
}
FieldWhat it does
voiceVoice settings to replace (provider, name, rate, gap, subtitles, volume, fit). It is merged key by key: what you leave out stays as the storyboard says.
narrationNew text. Either an object { "<line id>": "text" } that names only the lines it changes, or an array with the text of every line in order. A line's id is its id, else its position counted from 0.
overlaysSwaps the file of an overlay, keyed by its position in overlays counted from 0: { "0": { "src": "file" } }. Everything else about the overlay stays.
  • A variant only rewrites. Lines are timed to the recording, so a variant cannot add or remove one. If it names a line that does not exist, or an array has a different number of lines than the storyboard, loading fails and the error shows both counts.
  • Any other key in the file is an error. Every other field of the storyboard stays exactly as it was, and a storyboard rendered without a variant is unchanged.
  • Cards drawn from data cannot be changed by a variant yet.
  • Paths in the file are relative to the storyboard, as everywhere else.

Render a variant

screenpilot render storyboard.json --variant saudi
screenpilot render storyboard.json --variant variants/saudi.json -q draft

--variant takes a name (looked up as variants/<name>.json next to the storyboard) or a file path (a value with a folder or .json is a file). Over MCP, pass variant to render.

  • The output is <name>.<variant>.mp4, built in <name>.<variant>.build. With --style it is <name>.<variant>.<style>.mp4; then comes the format (.9x16) and the window (.part-12-20).
  • The voice cache is shared and keyed by text and voice. Rendering variant A, then B, then A again, renders A from the cache.
  • --dry-run prices the variant's text. See What cloud voices cost.

Variants in a sequence

screenpilot sequence all.json --variant saudi
screenpilot sequence all.json --variant saudi --variant-dir shared-variants
screenpilot sequence-validate all.json --variant saudi

Each storyboard part takes its own <part folder>/variants/saudi.json. A part that has none falls back to <variant-dir>/saudi.json. A part with neither renders as written, and the result warns about it. A variant that no part has fails. Over MCP: variant and variant_dir on sequence_render and sequence_validate.

  • The output is <sequence>.<variant>.mp4.
  • A part that has the variant gets its own folder and cache key for it (the name and the hash of the file). Parts without it, and finished {video} parts, are shared between variants, so a second variant renders only the parts that differ.
  • sequence-validate --variant checks the sequence with the variant applied, so a wrong line count shows before a render.

Slot-fit: does each line fit its slot?

The slot of a narration line is the time from its at to the next line's at, minus voice.gap. The last line has no slot. When the voice clip is longer than the slot, the render freezes the video to make room. That works, but a freeze in the middle of an action looks odd. Slot-fit tells you which lines cause it.

Once the voice clips exist, a render reports them in fit: one entry {id, raw, slot, needed} for every line whose clip is longer than its slot. raw is the clip's length in seconds, slot is the room in seconds, and needed is the speed-up that would make it fit (1.25 means 25% faster). A line above the cap also gives a [narration-fit] warning.

FlagMCP inputWhat it does
--fit-max <x>fit_maxThe cap, as a speed-up factor. Default voice.fit.max, else 1.18, the fastest that still sounds natural.
--fitfitSpeed up clips that overrun, up to the cap (ffmpeg atempo). The sped-up clip is cached next to the raw one (<clip>.x1.180.mp3) and is always made from the raw clip, so a re-render never stretches twice. Also set by voice.fit.auto in the storyboard.
--strict-fitstrict_fitFail instead of freezing when a line needs more than the cap.

The flags work on render and sequence. Ready-made audio (narration[].audio) is reported but never stretched. If a line still overruns after the speed-up, the warning says so, and the fix is shorter text.

"voice": { "name": "en-US-AndrewNeural", "fit": { "max": 1.15, "auto": true } }

screenpilot sequence-validate --fit (MCP sequence_validate fit: true, fit_max) checks the clips that are already in the voice cache without making any, and counts the lines that have none. Turn the warning off with lint.off: ["narration-fit"].

Variants and slot-fit work together: a longer wording in another language is the usual reason a line stops fitting. Render the variant with --fit or read the fit list and shorten the text.
