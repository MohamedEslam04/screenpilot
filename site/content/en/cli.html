The command line does the same steps as the MCP tools. Run it as screenpilot, or as node dist/cli.js from a source checkout. Most people never need it, because their AI app calls the tools for them. Use the CLI to script a render, to check a machine, or to repair a setup.

Run screenpilot --help for the list of commands and screenpilot <command> --help for the flags of one command. Commands print their result as JSON on stdout and progress messages on stderr.

The whole workflow

This block takes a recording to a finished video. Replace the paths and the voice with your own.

# 1. Record the screen. Press Enter or Ctrl+C to stop.
screenpilot record

# 2. Find idle time and clicks, and get a contact sheet image.
screenpilot analyze sessions/2026-10-27_14-02

# 3. Look closer at moments, with a 0..1 coordinate grid.
screenpilot frames sessions/2026-10-27_14-02/video.mkv --at 1,4.5,10 --grid

# 4. Write a starter storyboard (idle time cut, click zooms filled in).
screenpilot init sessions/2026-10-27_14-02 --suggest --voice ar-EG-SalmaNeural

# 5. Edit storyboard.json, then check it.
screenpilot validate sessions/2026-10-27_14-02/storyboard.json

# 6. Render a fast draft and look at frames of the result.
screenpilot render sessions/2026-10-27_14-02/storyboard.json -q draft
screenpilot check sessions/2026-10-27_14-02/storyboard.mp4 --at 2,8,15

# 7. Render the final video.
screenpilot render sessions/2026-10-27_14-02/storyboard.json -q delivery -o demo.mp4
Times in a storyboard and in frames --at are source seconds (the raw recording). Only check --at uses output seconds (the rendered video). See the storyboard reference.

Record and look

record

Records the screen and logs pointer events. Press Enter or Ctrl+C to stop, or pass --duration. It prints the session folder with the video, events.jsonl and windows.jsonl. Recording is native by default, so OBS is not needed.

FlagWhat it does
-d, --dir <dir>Session folder. Default: sessions/<timestamp>.
--duration <s>Stop automatically after this many seconds.
--screen <name>Monitor being recorded, for example eDP-1. Default: the one under the cursor.
--screens <list>Record several monitors side by side: all, or names such as HDMI-A-5,eDP-1.
--fit-window <match>Resize the window whose class or title contains this text to 16:9 while recording. It is restored afterwards.
--recorder <how>native (no OBS) or obs. Default: native when available.
--input <adapter>Pointer and click capture: auto (default), kwin, uiohook or none.
--obs-url <url>, --obs-password <pw>obs-websocket connection, when you record through OBS. Defaults come from the OBS config, else ws://127.0.0.1:4455.
--map <pairs>OBS source to monitor, for example "PC Screen=eDP-1". It is remembered.

remap

screenpilot remap <session> --screen <name> re-maps the pointer events of a session to another monitor. Use it when record warns that it guessed which monitor OBS records, and the guess was wrong. The monitor names are in the session's meta.json under screens.

analyze

screenpilot analyze <session-dir|video> finds idle spans and clicks, suggests segments and zooms, and writes a contact sheet image of labelled thumbnails. Open the contact sheet first to understand the story of the recording.

FlagWhat it does
--frames <n>Thumbnails in the contact sheet. Default 12.

frames

screenpilot frames <video> saves still frames of the raw recording so you can see it. Times are source seconds.

FlagWhat it does
--at <times>Comma-separated seconds, for example 1,4.5,10.
--every <n>Instead of --at: this many evenly spaced frames. Default 12.
--gridDraw a 0..1 coordinate grid. Read zoom, highlight and callout positions from it.
-w, --width <px>Frame width. Default 1280.
-o, --out <dir>Output folder. Default frames.

Edit

init

screenpilot init <session-dir|video> writes a starter storyboard.json. It saves the file in the session folder, or next to the video, and it picks up events.jsonl when it exists.

FlagWhat it does
--suggestPre-fill segments, zooms and camera views from analyze.
--voice <name>Default Edge TTS voice. Default en-US-AndrewNeural.
--frame <how>Camera for suggested views: window (default), screen or all.
-o, --out <file>Storyboard path.
-f, --forceOverwrite an existing storyboard.

validate

screenpilot validate <storyboard> checks the file against the schema and the source video. It fails with the list of schema issues, or prints valid: true with warnings such as overlapping segments, items past the end of the video and callouts without x and y.

schema

screenpilot schema prints the storyboard JSON Schema. It is the authority on every field.

voices

screenpilot voices lists the available voices. It needs a network connection.

FlagWhat it does
--lang <prefix>Filter by locale prefix, for example ar, ar-EG or en-US.
--provider <id>Voice provider. Default edge.

Render and check

render

screenpilot render <storyboard> makes the voice, cuts the video and renders an MP4. It takes minutes. It prints the output path, the duration, the freezes it added (autoHolds) and warnings. When a narration line is longer than its slot, the render freezes the video so lines never overlap.

FlagWhat it does
-o, --output <file>Output video. Default <storyboard>.mp4.
-q, --quality <q>draft, looks or delivery. Default looks.
--png-framesUse lossless source frames: sharper text in the recorded UI, slower.
--workers <n>Parallel renderers, each a headless Chrome. Default 2.
--build-dir <dir>Where the HyperFrames project is written.

Quality levels

LevelUse it for
draftFast renders while you edit. Use this in every review loop.
looksA normal render. This is the default.
deliveryThe final file only. It is the slowest.

build

screenpilot build <storyboard> does everything except the final render: it generates the voice, cuts the video and writes the HyperFrames project. It prints the build folder, the output duration, automatic freezes and warnings. It accepts --build-dir <dir>.

preview

screenpilot preview <storyboard> builds the storyboard and opens HyperFrames Studio, where you can scrub through the video.

check

screenpilot check <video> pulls frames from a rendered video so you can review the result. Times are output seconds. It prints the duration, whether the video has audio, and the frame files.

FlagWhat it does
--at <times>Comma-separated output seconds.
--every <n>Evenly spaced frames. Default 8.
-o, --out <dir>Output folder. Default <video>.check next to the video.

See and drive the desktop

These commands let you look at the desktop and test a flow by hand before you write a take. The agent uses the same actions through the MCP tools. They use the real mouse and keyboard, so keep your hands off while one runs. Agent drive explains the whole loop, and Safety explains the limits.

screenshot

screenpilot screenshot saves a picture of each monitor.

FlagWhat it does
--screen <name>Only this monitor.
--gridOverlay a 0..1 coordinate grid.
-w, --width <px>Image width. Default 1280.
-o, --out <dir>Output folder. Default screens.

windows

screenpilot windows lists open windows with their position. On desktops without window control (GNOME and other Wayland desktops) the list is empty.

browser

screenpilot browser opens, or reuses, the clean demo browser and places it on a monitor. Flags: --screen <name> and --url <url>.

drive

screenpilot drive has four subcommands. Positions are screen,x,y with x and y from 0 to 1, for example eDP-1,0.5,0.5.

CommandWhat it does
drive move <screen,x,y>Move the pointer.
drive click <target>Click. The target is screen,x,y or web:<selector> for an element in the demo browser. Flags: --button left|right|middle (default left), --count <n> (2 for a double click).
drive type <text>Type text into the focused field.
drive key <combo>Press a key combination such as "ctrl+l". On macOS use cmd.

perform

screenpilot perform <take.json> performs a take on the real desktop while recording, then writes a session folder with the video, events and a ready storyboard. If a step fails, it prints the step number, the step and the error. Press Ctrl+C to stop a run.

FlagWhat it does
--dry-runDrive the desktop without recording. Always rehearse first.
-d, --dir <dir>Session folder. Default sessions/<timestamp>.

take-schema

screenpilot take-schema prints the JSON Schema of take.json.

Set up and check this machine

setup

screenpilot setup copies the app to its folder, adds ScreenPilot to every AI app it finds, and prepares the render browser. Restart the AI app afterwards. Config files are backed up before they change.

FlagWhat it does
--listList the AI apps setup knows and whether each is installed here.
--clients <ids>Only these client ids, for example claude-desktop,claude-code,codex,opencode,cursor.
--removeRemove ScreenPilot from those apps instead.
--output <dir>Where videos are saved. Default ~/Videos/ScreenPilot.
--in-placeRegister the package where it is, without copying it.
--skip-prepareDo not download the render browser or run the test render.
--allow-toolsClaude Code only: let the agent use every ScreenPilot tool without asking each time. It adds a rule to ~/.claude/settings.json.
--printOnly print the config to paste into an AI app by hand.

doctor

screenpilot doctor checks this machine: ffmpeg, desktop, monitors, OBS, the demo browser and voices. It prints a JSON report and a one-line summary. The exit code is always 0, so read the report. Add --input to also test input injection; this moves the real pointer for a moment.

Run screenpilot doctor first on a new machine, and again whenever recording or driving fails.
