The dashboard is a separate small desktop program. It shows everything ScreenPilot recorded and rendered, the renders running now, your voice providers and some numbers about your renders. It runs on your computer only and does not need an account.

The dashboard is new. For now you build it from the repository: it is not part of the main download yet. It has been tested with mocked data in a browser and with unit tests of its Rust logic. Its window has not been run on a real desktop in this repository's checks, so expect rough edges. The steps are in Build it.

Start the dashboard

Run this in a terminal:

screenpilot dashboard

It starts the program and returns at once. The dashboard is its own program with its own window.

ScreenPilot looks for the program in this order:

  1. The path in the SCREENPILOT_DASHBOARD_BIN environment variable, if you set it.
  2. The file screenpilot-dashboard (screenpilot-dashboard.exe on Windows) in the dashboard folder. This folder sits next to the app folder, with -dashboard added to its name, because setup replaces the app folder every time it runs.
  • Linux: ~/.local/share/screenpilot-dashboard
  • Windows: %LOCALAPPDATA%\ScreenPilot-dashboard
  • macOS: ~/Library/Application Support/ScreenPilot-dashboard

If the program is not there, screenpilot dashboard says it is not installed and names the folder it looked in.

On Linux, screenpilot setup adds a ScreenPilot entry to your application menu when the dashboard program is already in that folder. screenpilot setup --remove removes the entry.

Build it

You need Rust. On Linux you also need the WebKitGTK 4.1 development packages. The repository's dashboard/src-tauri/README.md lists the package names for Fedora.

cargo install tauri-cli --locked
cd dashboard/src-tauri
cargo tauri build

Put the program it builds in the dashboard folder above, or point SCREENPILOT_DASHBOARD_BIN at it.

What it shows

The window has four tabs.

Library

The Library lists your recordings, takes, renders and sequences from history.jsonl, newest first, with a thumbnail for each video. It loads 50 rows at a time, and Load older adds more. Type in the search box to search the loaded rows (press / to jump to it). The buttons above the list filter by kind (Records, Takes, Renders, Sequences) or show only failed work.

Select a row to open the detail panel:

  • A video player, when the work has a video.
  • The kind, time, status, duration, quality, how long it took, and the paths. A failed job shows its error.
  • A summary of the storyboard: output size, voice, source, and how many narration lines, captions, zooms, highlights and segments it has. A sequence lists its parts.
  • The narration lines with their times.
The player and the thumbnails read files under your home folder, /data, /mnt and /run/media. A video somewhere else, such as another drive on Windows, does not play in the window. Open video still opens it.

Live

The Live tab lists the renders running now, with the quality, the time elapsed and a progress bar when the render knows its step (chunk 3 of 12, or part 2 of 4). It updates when a render moves to its next step. A number on the tab shows how many are running. It lists renders started from anywhere: the dashboard, the command line or your AI app.

Voices

The Voices tab shows one card for each provider: edge, local, command, elevenlabs and gemini. Each card says whether a key is set (and whether it comes from an environment variable or from the saved file), where the narration text goes, and lists the voices of that provider. For ElevenLabs and Gemini you can paste a key and save it, or remove a saved key. Voices explains the providers.

Stats

The Stats tab shows how many events the history holds, the render speed for each quality (video seconds made per second of waiting, from your finished renders, with the number of runs), and the size of the render cache. The cache is measured when you open the tab, and a button measures it again. A large cache can take a while.

What you can do

These buttons are in the detail panel of a row:

ButtonWhat it does
Open videoOpens the video with your default player.
Show in folderOpens the folder that holds the video or the session.
Render draftRuns screenpilot render on the storyboard with -q draft. It starts in the background. Follow it on the Live tab.
Render deliveryThe same at delivery quality. You click twice: the button first asks you to confirm.
Copy commandCopies the command to your clipboard so you can run it yourself.

The render buttons appear for a render and for a take that wrote a storyboard. A sequence only has Copy command, which copies a screenpilot sequence command.

The dashboard opens only videos, images, subtitles, audio and text files. It refuses to open anything else, such as a program or a script. Show in folder works for any file, because it only shows it in its folder.

Work from before the history

The Library reads history.jsonl. Recordings and renders you made before the history existed are not in it. Add them from a terminal:

screenpilot library import

See library for the folders it looks in.

How keys are stored

When you save a key on the Voices tab, the dashboard does not keep it. It sends the key to screenpilot secret set on standard input, and ScreenPilot writes it to secrets.json in the config folder with file mode 0600. The dashboard never shows a key again, and it never reads secrets.json. A key set by an environment variable cannot be changed or removed there. secret has the same commands for the terminal.

Why it stays light

  • No background process. Closing the window ends the program.
  • It watches the folder of running jobs only while the window is shown. There is no polling loop.
  • The list draws only the rows you can see, and loads older rows when you ask.
  • Each thumbnail is made once, when its row first appears, by ffmpeg. It is saved in the thumbs folder of the cache folder and reused.

Local only

The dashboard window makes no network requests. It reads files on your computer and runs the screenpilot command. One exception is the voice list of an online provider: it runs screenpilot voices, which contacts that service.

More commands are in the command line page: history, library and secret.
