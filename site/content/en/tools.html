ScreenPilot runs as an MCP server. Your AI app sees the tools below and calls them for you, so you ask for a video in plain words and the app picks the tools. This page is for developers who want to know exactly what each tool does. The server also sends the workflow to every client when it connects, so apps without a skill know the loop too.

Times in storyboard tools are source seconds (the raw recording). Positions are normalized 0..1, with x from the left and y from the top. Only check_output uses output seconds.

Updates

ToolWhat it doesKey inputs
update_checkSays whether a newer release exists (it asks GitHub and changes nothing): up-to-date, available, or blocked with the reason and the full download link. It returns the command the user runs in a terminal to update. There is no tool that updates: the AI app tells you the command and you run it.none

Decisions first

Before any recording or render, the AI app must ask you how the video should be made: goal, source, language, which voice (built-in, a website's, your own, or none), look, camera, review and permissions. The recommended option is not fixed: it follows the existing video in the folder (its voice files, language and size), then your usual choices from last time, then the plain defaults. Describing the content is optional. record_start, perform, render and sequence_render refuse until you answered.

ToolWhat it doesKey inputs
briefAsks you the decisions as option pickers. If your AI app can show forms, you pick right there. Before the detailed questions it shows the whole recommended setup as a list, including the permissions answer, and asks once: use it, or choose each item. If you accept, the app calls brief with use_recommended: true (never on its own). Otherwise it returns the pickers (2 to 4 options each, the recommended one first) for the app to show you, and the app calls brief again with your answers. When everything is answered it returns the answers and the next steps, and remembers your choices (never the content) as your usual ones. Options that need something this computer does not have say so, for example a local voice model that is not installed.answers, via_agent, reset, use_recommended, project (folder or storyboard.json the recommendations follow; default the server's folder)

Set SCREENPILOT_SKIP_BRIEF=1 for unattended runs that have nobody to ask.

Storyboard

With suggest, it pre-fills segments (idle time cut) and zooms (from clicks). provider is edge (default), local or command, and voice is the voice name for it, for example voicetut:Sarah.target, suggest, out, voice, provider, force

Render and check

ToolWhat it doesKey inputs
renderRenders a storyboard to MP4. It takes minutes. When a narration line is longer than its slot, the video freezes automatically (see autoHolds in the result). Use draft while iterating, looks for a normal render, and delivery only for the final file. Pass from and to (output seconds) to re-render only that window for a fast review: the file is <storyboard>.part-<from>-<to>.mp4. Pass formats to render one file per format, narration generated once.storyboard, output, quality (draft, looks, delivery; default looks), from, to, formats, subtitles, languages, subtitle_chars, also, poster_at, style, variant, fit, strict_fit, fit_max, workers, chunks, chunk_seconds, dryRun, min_free_mem, mem_timeout
check_outputReturns frames of a rendered video as images, at most 12 per call. Times here are output seconds. Without times you get 8 evenly spaced frames. Look for clipped captions, zooms on the wrong spot and awkward freezes. When <video>.timeline.json exists, it also checks that each narration line's sound starts within 0.4 seconds of its caption time and lists the lines that do not as warnings.video, times, sync (false skips the sync check)
subsWrites caption files for a video that is already rendered, from its <video>.timeline.json, with no render: <video>.<code>.srt|vtt per language. languages is {"ar": "auto", "en": "en.json"}: auto is the video's own lines, a path is a translation file you or the app wrote (no machine translation). For a video joined outside ScreenPilot, pass join (the part timelines in order) and transition. mux: true also adds the files as soft subtitle tracks into <video>.subs.mp4 without re-encoding. See Subtitles and timeline.video, languages, formats, subtitle_chars, join, transition, transition_type, mux
buildGenerates the voice, cuts the video and writes the HyperFrames project without rendering. Reports the output duration, automatic freezes and warnings.storyboard
previewBuilds the storyboard and opens HyperFrames Studio so a person can scrub through it.storyboard

The formats input is a list of strings, each "16:9", "9:16", "1:1" or "WxH" such as "1280x720". It writes <storyboard>.<format>.mp4 (labels 16x9, 9x16, 1x1, WxH), and then output becomes the base name. The result is one entry per format. A portrait export crops landscape views that frame a window. See Several formats.

subtitles (a list of "srt" and "vtt") writes caption files from the narration next to the video. With languages it writes one file per language, <video>.<code>.srt|vtt, from the video's own lines ("auto") or a translation file; subtitle_chars sets the line width. also (a list of "gif", "webm" and "poster") makes an animated GIF, a WebM or a poster PNG from the finished video, and poster_at sets the poster's time in output seconds. Every file written is listed under files in the result.

style is the path of a style file, JSON with only a theme. Its theme is merged over the storyboard's, the file is named <storyboard>.<style>.mp4 and each style keeps its own build folder. See Variants.

variant is a variants file, or its name (looked up as variants/<name>.json next to the storyboard): the same recording with another script and voice. The file is named <storyboard>.<variant>.mp4 and keeps its own build folder. fit, strict_fit and fit_max control slot-fit: the result's fit lists narration lines whose clip is longer than their slot, fit: true speeds such clips up to the cap, strict_fit: true fails instead. See Script variants and slot-fit.

dryRun: true sends nothing and writes nothing: it returns the lines, characters and estimated USD the voice would cost (cached lines are free). Call it before the first render with a paid voice. See What cloud voices cost.

The video is written as <name>.partial.mp4 and renamed when complete. The result lists the timeline file (when each narration line is on screen), has peakRssMB (the highest memory of the render's child processes) and fit. A render waits before each chunk until min_free_mem MB are available (default 1500, 0 is off) for at most mem_timeout seconds (default 300). See Long renders.

workers is "auto" (default: half the cores), "max" (all cores but two: faster, but the desktop gets sluggish, so use it when the user is away) or a number. The environment variable SCREENPILOT_WORKERS sets the default. When a render is expected to take 2 minutes or more, the log starts with estimated ~<time> from past renders.

A video (or a from/to window) of 5 minutes or more renders in chunks of about 3 minutes, cut where nothing is moving or speaking. Each chunk is cached, so after an edit only the chunks it touched render again, then all are joined. chunks: false renders in one piece; chunk_seconds (at least 10) sets the chunk length. See Long renders. A long render can be stopped with abort or paused with pause and carried on with resume; see Pause and resume.

Combine recordings

These tools join several storyboards, each with its own recording, into one video, for example to insert a feature clip into an existing demo without re-recording it. The file format is in Combine recordings.

ToolWhat it doesKey inputs
sequence_schemaReturns the JSON Schema of sequence.json. Read it before you write a sequence.none
sequence_validateValidates a sequence and every storyboard it uses. Returns valid with warnings, or the issues. It never throws. variant (and variant_dir) checks it with a variant applied. fit: true also checks that narration lines fit their slots from the clips already in the voice cache (nothing is synthesized; lines without a clip are counted as unchecked), with fit_max as the cap.path, variant, variant_dir, fit, fit_max
sequence_renderRenders each part like a storyboard (unchanged parts are reused), all at one output size, with the intro of the first part and the outro of the last, then joins them into one MP4. Pass style (a style file with only a theme) to render the same sequence with another look: the file is named <sequence>.<style>.mp4, each style keeps its own build folder and cache, and finished video parts are not styled. Pass variant to render it with another script: each part takes <its folder>/variants/<name>.json (else <variant_dir>/<name>.json), a part with none renders as written with a warning, and the file is named <sequence>.<variant>.mp4. fit, strict_fit and fit_max work as in render. subtitles, languages and subtitle_chars write caption files for the joined video from its timeline (a translation is {"<chapter>": ["line", ...]}). dryRun: true returns the voice cost part by part and writes nothing. It also writes <sequence>.timeline.json, waits for min_free_mem and mem_timeout before each part or chunk, and returns peakRssMB. For several videos from the same groups, pass joins ({name: [sequence files or names of other videos]}, for example {setup: ["g1.json", "g2.json"], operations: ["g3.json"], full: ["setup", "operations"]}) instead of sequence, with join ({transition, dur}: how each group enters from the one before it, dur default 0.5 s, at most half of either group) and out_dir (default: the folder that holds all the groups). Every group is rendered once and reused, and each video is <out_dir>/<name>.mp4 with its own <name>.timeline.json (and caption files) and a length of the sum of its groups minus one dur per join. output is refused with joins, and join and out_dir need joins. pause and resume take sequence <out_dir>/joins for it. The result lists each video and each group, and whether the group was rendered or reused. It takes minutes. Follow it with check_output.sequence or joins, join, out_dir, output (default <sequence>.mp4), quality, style, variant, variant_dir, fit, strict_fit, fit_max, subtitles, languages, subtitle_chars, workers, dryRun, min_free_mem, mem_timeout
pausePauses a running render or sequence_render, for example when the user needs the machine. It finishes the part in progress (the chunk, for a part or video of 5 minutes or more) and stops. That call returns {paused: true, parts: [{part, status}], resume} with each part done, in progress or waiting. With neither sequence nor storyboard it pauses every render running now.sequence or storyboard, build_dir

Pause and resume a render

resume has two uses. With sequence or storyboard, it carries on a render that was paused with pause, with the options the render started with. Every finished part and chunk is reused, so only the rest renders, and it can be paused again. You may change workers, min_free_mem and mem_timeout. Without arguments, it keeps its older job: carrying on after someone moved the mouse. abort stops a running render with its whole process tree and removes the partial file. See Long renders.

See and drive the desktop

These tools let the agent look at the screen and act on it. Drive tools use the real mouse and keyboard. Read Agent drive for the loop and Safety for what the agent can touch and how to limit it. Every drive action is logged to audit.jsonl in the config folder. Typed text is never logged.

These tools only read.

screenshotReturns a picture of each monitor. With grid on, a 0..1 grid shows the x and y to pass to pointer_move and click. Take one before an action and one after, to verify.screen, grid, width
windowsLists open windows: id, title, class or app, pid, whether active, geometry and monitor. Empty on desktops without window control (GNOME, sway); use screen targets there.none
browser_openOpens, or reuses, the clean demo browser (its own profile) and places it on a monitor. app hides the address bar and tabs, so nothing about the machine shows. For a second browser (an admin and a user side by side) pass an id: it has its own profile and window, and an id that is already open is reused and navigated, never started twice. See Two demo browsers.screen, url, app, id
web_locateFinds an element in the demo browser by Playwright selector (CSS, text=..., role=...) and returns its rectangle in screen pixels. Use it to check that a target exists before you click. Pass browser for a second demo browser.selector, browser
a11y_treeReads a native app's UI as data through the OS accessibility tree: nested controls with role, name, states and a rectangle in screen pixels. Cheaper and more exact than a screenshot. Use it to find the role and name for an {a11y} target. By default it covers the focused window's app and only controls. Read-only.app, interactiveOnly (default true), maxDepth (20), maxNodes (1500)

Targets

click, drag and scroll take a target. There are four forms:

  • {web: selector}: an element in the demo browser, by Playwright selector. This is the most reliable form.
  • {a11y: {role, name, app, exact, nth}}: a control in a native app, found through the accessibility tree. Give a role or a name. Look it up with a11y_find first. See Native apps.
  • {screen, x, y}: a point on a monitor, normalized 0..1. screen is optional.
  • {window, x, y}: a point inside the window whose class or title contains the text, normalized 0..1.
On GNOME and other Wayland desktops there is no window control. Use {screen, x, y} targets there; {a11y} controls can be read but not clicked. Run doctor to see what the desktop supports.

Abort and resume

If a person moves the mouse while the agent drives, the running action stops with a message. This protects the person at the machine. For unattended runs, start the server with SCREENPILOT_INTERRUPT=off.

ToolWhat it doesKey inputs
resumeWith no arguments: carries on after a click, move or type stopped because someone else moved the pointer. It adopts the pointer where it is now and keeps the driver open, so no new approval dialog appears. Take a screenshot afterwards: the screen may have changed.none
abortStops whatever the agent is driving: the live driver and a running perform, and any running render or sequence_render with its whole process tree (HyperFrames, Chrome, ffmpeg); the partial video is removed and finished chunks and parts stay cached. Safe to call any time. The next drive tool opens a fresh driver.none
The first drive action can need a person to approve a remote-control dialog (once, on Wayland; the approval is saved). On macOS, the AI app needs Accessibility and Screen Recording permission. The error says where to grant it.
