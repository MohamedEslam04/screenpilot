Subtitles and timeline

Write caption files in several languages from the timeline file of a rendered video, without rendering again, add them as soft tracks, and check that the captions land on the sound.

Platforms such as YouTube, LinkedIn and Vimeo take caption files, and a video for several countries needs one file per language. ScreenPilot makes them from the timeline file that every render writes, so a new language never needs a new render. It does not translate anything: you (or your AI app) write the translations, and ScreenPilot places them at the right times.

The timeline file#

Every render and every sequence writes <video>.timeline.json next to the video. It lists when each narration line and each title card is on screen, in output seconds.

{
  "version": 1,
  "duration": 74.2,
  "items": [
    { "kind": "narration", "id": "open", "start": 1.2, "end": 4.9, "text": "We open the settings." },
    { "kind": "card", "start": 12, "end": 14.5, "text": "Step two\nThe settings page" }
  ]
}
  • kind is narration (a spoken line), card (the intro or a chapter card; text is its title, then its subtitle on a second line) or outro. Cards drawn from data (Cards from data) are not listed.
  • id of a narration item is the line's id from the storyboard. Without an id it is the line's position, counted from 0.
  • A sequence writes one timeline for the joined video. Each part also keeps its own next to its part.mp4, so parts reused from the cache still count. In a sequence, an item also has part (the index of the part) and chapter (the name of the part's storyboard folder).
  • The result of a render or sequence lists the file under timeline.
A timeline whose duration differs from its video by more than 0.25 seconds is stale, for example after you trimmed the video by hand. Every command that reads it stops with an error that names the file.

Name your narration lines#

A translation is matched to a line by its id. Give each narration line a short, unique id. Lines without one are matched by position from 0, which breaks when you insert a line.

"narration": [
  { "id": "open", "at": 1, "text": "We open the settings." },
  { "id": "save", "at": 6, "text": "Then we save." }
]

A repeated id makes the match ambiguous, so keep them unique.

Translation files#

A translation file is plain JSON that you write. For one storyboard it maps an id (or position) to the translated line:

{ "open": "Abrimos los ajustes.", "save": "Guardamos." }

For a sequence, the keys are chapters, which are the folder names of the part storyboards. A chapter holds either an array with exactly one line per narration line of that chapter, or an object keyed by id:

{ "setup": ["Abrimos los ajustes.", "Guardamos."], "ops": { "done": "Listo." } }
  • A line that has no translation is an error that names its id.
  • An array with the wrong number of lines is an error that names the chapter and both counts.
  • A key that matches nothing is only a warning.

The paths of translation files are read from the folder you run the command in.

Caption files at render time#

Add --subtitle-lang to render or sequence. It takes a comma list. A plain code (ar) uses the video's own lines. code=file (en=en.json) uses a translation file.

screenpilot render demo.json --subtitle-lang ar,en=en.json,es=es.json
screenpilot sequence all.json -q delivery --subtitle-lang ar,en=en.json,es=es.json --subtitles srt,vtt
  • The files are <video>.<code>.srt and <video>.<code>.vtt, for example all.ar.srt. --subtitles picks the formats (srt, vtt or both). With --subtitle-lang and no --subtitles, both are written.
  • --subtitle-chars <n> sets the characters per caption line. Default 42.
  • Without --subtitle-lang, render --subtitles writes the plain <video>.srt and .vtt exactly as before.
  • Over MCP, render and sequence_render take languages ({"ar": "auto", "en": "en.json"}, where auto means the video's own lines), subtitles and subtitle_chars.

Translation files are read and checked before the render starts, so a typo fails in seconds, not after a long render.

Captions for a video that is already rendered#

screenpilot subs <video> reads <video>.timeline.json and writes the caption files. It renders nothing, so adding a language later takes a second.

screenpilot subs demo.mp4 --lang ar,en=en.json --formats srt,vtt
FlagWhat it does
--lang <list>Languages, as for --subtitle-lang. Without it, one plain <video>.srt and .vtt.
--formats <list>srt, vtt or srt,vtt. Default srt,vtt.
--chars <n>Characters per caption line. Default 42.
--join <list>For a video you joined outside ScreenPilot: the timelines of its parts, in order (a.timeline.json,b.timeline.json), instead of <video>.timeline.json.
--transition <s>With --join: how many seconds each part overlaps the one before it. Default 0, which means cuts.
--transition-type <type>With --join and --transition: crossfade (default), fade-black, wipe-left and so on. The overlap is the same for all of them.
--muxAlso add the files to the video as soft tracks. See below.

The MCP tool is subs (inputs video, languages, formats, subtitle_chars, join, transition, transition_type, mux). With --join, the parts are composed with the same arithmetic as sequence: the overlap of a transition is limited to half of either part.

Soft subtitle tracks#

--mux (MCP mux: true) adds the caption files to a copy of the video, with the language set on each track, so a player can offer a language menu. The copy is <video>.subs.mp4 (the same extension as the video). Nothing is re-encoded and your original is untouched. The track format is mov_text for mp4 and mov, and webvtt for mkv and webm.

screenpilot subs all.mp4 --lang ar,en=en.json,es=es.json --mux
# writes all.ar.srt, all.en.srt, all.es.srt (and .vtt) and all.subs.mp4 with 3 language tracks

How captions are cut#

All caption files follow one set of rules:

  • At most 2 lines per caption, about 42 characters each. Lines break on spaces only, so a long word stays whole.
  • A narration line that is longer becomes several captions.
  • No caption overlaps the next one, and each lasts at least 0.7 seconds when there is room.
  • Right-to-left text (Arabic, Hebrew) is never reordered and no direction marks are added.

Check that captions land on the sound#

When <video>.timeline.json exists, screenpilot check <video> (MCP check_output) also compares the time of each narration line with the first sound after it. It warns about every line where they are more than 0.4 seconds apart. --no-sync (MCP sync: false) skips the check.

Background music keeps a video from ever being silent, so the check cannot see a problem in a video that has music.

A complete example, from a sequence with two chapters to three languages:

screenpilot sequence all.json -q delivery --subtitle-lang ar,en=en.json,es=es.json --subtitles srt,vtt
screenpilot check all.mp4 --every 8
screenpilot subs all.mp4 --lang ar,en=en.json,es=es.json --mux
