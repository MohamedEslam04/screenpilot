Voices

Choose a narration voice: Edge, cloud voices with your own ElevenLabs or Gemini key, speech models on your computer, or any program you define. Setup and fixes.

ScreenPilot speaks each narration line with a voice provider. There are five. edge is the default and needs no setup. elevenlabs and gemini are cloud voices that use your own account key. local runs speech models on your own computer. command runs any program you define that turns text into an audio file. Existing storyboards keep working: when a storyboard has no provider, it is edge.

Choose a provider#

ProviderWhat it isInternetCostQuality note
edgeMicrosoft Edge voices, in many languages, including Egyptian Arabic.Needed for every render of new lines.None.Works with no setup. It is an unofficial service and may change.
elevenlabsElevenLabs cloud voices, with your own API key.Needed for every render of new lines.Depends on your ElevenLabs plan. Free plans have limits.High quality. Your narration text is sent to ElevenLabs. Optional: needs an account.
geminiGemini API cloud voices from Google, with your own API key.Needed for every render of new lines.Depends on your Google quota. Free tiers have limits.Your narration text is sent to Google. Optional: needs an account.
localSpeech models that run on your computer: VoiceTut and NAMAA.Only for the setup download. Not needed after.Free. Uses about 10 to 16 GB of disk.Egyptian Arabic and English. Arabic is less accurate than English. Tested on Linux with an NVIDIA GPU only.
commandA program you define in voices.json, for example Piper.Depends on the program.Depends on the program.Whatever the program produces.

Pick edge if you want it to work now. Pick elevenlabs or gemini if you already have an account and want a cloud voice. Pick local if you want no internet at render time. Pick command if you already have a speech model of your own.

Set the provider once for the whole storyboard in voice. See Output and voice for every field.

Edge voices#

Edge is the default provider. The voices are Microsoft Edge voices, fetched over the internet. The service is unofficial, so it can change or stop without notice. A video with no narration lines needs no voice, and generated clips are cached, so an unchanged line is not requested again.

"voice": { "name": "ar-EG-SalmaNeural", "rate": "+0%" }

List the voices, optionally for one language:

screenpilot voices --lang ar-EG

Examples: ar-EG-SalmaNeural, ar-EG-ShakirNeural, en-US-AndrewNeural (the default), en-US-AriaNeural.

Cloud voices: ElevenLabs and Gemini#

These two providers send each narration line to a cloud service and get audio back. They are optional. ScreenPilot still needs no account by default, and a storyboard without elevenlabs or gemini never contacts either service. You bring your own key.

The narration text is sent to ElevenLabs or Google. Do not use these providers for text you cannot share with them. Free plans have limits and may forbid commercial use. Read the current terms of the service before you publish a video.

Set your API key#

Each provider reads one key. The environment variable wins over a stored key.

ProviderEnvironment variable
elevenlabsELEVENLABS_API_KEY
geminiGEMINI_API_KEY

To store a key instead of exporting it, pipe it into screenpilot secret set. The key is read from standard input, never from an argument, so it stays out of your shell history and the process list. It is saved in secrets.json in the config folder, with file mode 0600 on Linux and macOS (only you can read it). Windows has no file modes, so there the file is protected only by the permissions of your user profile folder.

printf '%s' "$ELEVENLABS_API_KEY" | screenpilot secret set elevenlabs
screenpilot secret status
screenpilot secret remove elevenlabs
  • secret status says for each provider whether the key comes from env, from file, or is not set. It never prints a key.
  • secret remove deletes the stored key. It cannot unset an environment variable.
  • If you run secret set in a terminal without piping, it asks you to paste the key and press Enter.

A key is never written to a log, a cache key or an error message. screenpilot doctor has an "elevenlabs voice" and a "gemini voice" line. It is skipped when no key is set, because the providers are optional. With a key, it makes one cheap request to the host in use (it costs no credits and sends the key only as a header), so a key made for another region shows up there and not in the middle of a render.

Region and base URL (data residency, gateways)#

A key belongs to one host. An ElevenLabs account with data residency (EU, India or Singapore) has its own API host, and the default host api.elevenlabs.io refuses its keys with 401 invalid_api_key. A company may also put a gateway in front of a provider. Tell ScreenPilot which host to use:

screenpilot endpoint set elevenlabs eu        # us | eu | in | sg, or a full https address
screenpilot endpoint set gemini https://gateway.example.com/gemini
screenpilot endpoint status                   # the host in use and where it comes from
screenpilot endpoint clear elevenlabs         # back to the default host
screenpilot doctor                            # checks the key against that host
  • The address is saved in voices.json ("providers": {"elevenlabs": {"baseUrl": "..."}}). The environment variables ELEVENLABS_BASE_URL and GEMINI_BASE_URL win over the file. The dashboard Voices tab has the same field.
  • It is never read from a storyboard, so a shared project cannot send your key to another host.
  • Write it with or without the API version (/v1); a trailing slash is ignored. It must start with https:// (http:// is allowed only for localhost) and must not contain a user name or password.
  • Region names: us = api.us.elevenlabs.io, eu = api.eu.residency.elevenlabs.io, in = api.in.residency.elevenlabs.io, sg = api.sg.residency.elevenlabs.io.
  • Clips made through another host are cached separately. Clips made through the default host stay valid.

ElevenLabs#

"voice": { "provider": "elevenlabs", "name": "Your Voice Name", "rate": "+0%" }
  • name is a voice id (20 letters and digits) or the name of a voice on your account. A name is looked up in your account, ignoring case. The default name belongs to Edge, so always set it.
  • The model is eleven_multilingual_v2. Set ELEVENLABS_MODEL_ID to use another one.
  • rate becomes the speed of the voice, limited to 0.7 to 1.2. For example +10% is 1.1. With +0% no speed is sent, so the settings stored for the voice apply.
  • ScreenPilot asks for 2 lines at a time, because the free plan allows 2 requests at once.

List the voices on your account:

screenpilot voices --provider elevenlabs

Gemini#

"voice": { "provider": "gemini", "name": "Kore" }
  • name is one of the 30 prebuilt Gemini voices, for example Kore, Puck, Charon, Zephyr or Fenrir. screenpilot voices --provider gemini lists all of them. They speak every language the model supports, and the language is detected from the text.
  • The model is gemini-3.8-flash-tts. Set GEMINI_TTS_MODEL to use another one.
  • rate is ignored: the Gemini API has no speed setting.
  • If the service sends no audio, ScreenPilot says so. The text may have been blocked.
screenpilot voices --provider gemini

Caching and retries#

  • Generated clips are cached by provider, voice, model, rate and text. An unchanged line is not requested again, so a repeat render uses no quota. Changing the model makes the lines again.
  • A request that fails because the network dropped, the service is busy (429) or has an error (5xx) is tried again, up to 3 tries in total. Any other error stops at once and the message names the service.

What cloud voices cost#

ElevenLabs and Gemini charge for what they speak. ScreenPilot keeps a ledger of what you used, and can tell you the price of a render before it makes any request.

Estimate before you render#

Add --dry-run to render or sequence (MCP dryRun: true). It prints how many lines the voice would send, how many characters that is and the estimated USD, then stops. It sends nothing and writes nothing: no cache entry and no build folder.

screenpilot render storyboard.json --dry-run
screenpilot sequence all.json --variant saudi --dry-run
  • Lines already in the voice cache, and lines that have ready-made audio, are free and are counted as cached.
  • With --variant, it prices the variant's text. For a sequence it reports part by part.
  • Edge, local and command voices cost nothing, so the estimate is 0.
Run the dry run before the first render with a paid voice, and read the number before you go on.

The spend ledger#

Every billed request adds one row to spend.jsonl in the config folder: {t, provider, model, voice, chars, audio_s, credits, usd}. A cache hit, a failed request and a free voice add nothing. The key and the text are never written. screenpilot spend totals the ledger by provider; --since 2026-11-01 limits it to a date and --json prints the rows. The MCP voices tool returns the running total as a second block.

screenpilot spend
screenpilot spend --since 2026-11-01 --json

Set your price#

The cost is an estimate, not an invoice. A credit is one character for ElevenLabs and one audio token for Gemini (25 tokens per second of speech). ScreenPilot multiplies credits by a price per credit. The defaults are 0.0003 USD for ElevenLabs and 0.00001 USD for Gemini. Your plan may differ, so set your own in voices.json:

{ "spend": { "usdPerCredit": { "elevenlabs": 0.00022, "gemini": 0.00001 } } }

ElevenLabs Flash and Turbo models use half a credit per character, so halve the price for them. SCREENPILOT_NO_SPEND=1 stops writing the default ledger.

Local models#

Local voices are speech models that run on your own computer. They are free and need no internet after setup. Install one with screenpilot voice-setup, then use it in a storyboard.

Which model to install#

  • VoiceTut speaks Egyptian Arabic and English and has 19 built-in voices. Start here. Its code is Apache-2.0; check the model page for the weights license. Its authors report a word error rate of 0.40 for Arabic against 0.07 for English, so listen to Arabic lines before you deliver. Sarah and Mohammed were tested here.
  • NAMAA speaks Egyptian Arabic only and has one voice. It is MIT licensed. Its model card says it can miss the "ق" sound and misread numbers.

Install a model#

Run this in a terminal. The MCP server has no tool for it on purpose, because it downloads many gigabytes and installs third-party code.

screenpilot voice-setup voicetut
screenpilot voice-setup namaa

What you need and what happens:

  1. Install uv. It also fetches Python 3.11, so you do not need your own Python.
  2. Run the command. It checks the free disk space first, and asks you to confirm unless you pass --yes.
  3. It creates a Python environment of its own and installs PyTorch: the CUDA build on NVIDIA GPUs, the CPU-only build on other Windows and Linux machines.
  4. It installs third-party code pinned to the commits it was tested with: OmniVoice and VoiceTut from GitHub for VoiceTut, and chatterbox-tts for NAMAA.
  5. It downloads the model and speaks one test line.
  6. It saves the Python path in voices.json (keys local.python and local.env.HF_HOME).
ModelDisk
voicetutAbout 10.5 GB, up to 15 GB while installing.
namaaAbout 5.5 GB more, on top of VoiceTut.

The models go in a folder next to the app folder, so an app update does not remove them:

  • Linux: ~/.local/share/screenpilot-voices
  • Windows: %LOCALAPPDATA%\ScreenPilot-voices
  • macOS: ~/Library/Application Support/ScreenPilot-voices
FlagWhat it does
--dir <path>Use another folder or drive.
-y, --yesDo not ask before downloading.
It can take 30 minutes or more on a slow connection. Do not close the terminal.

To use a Python you already have, set SCREENPILOT_LOCAL_PYTHON to a Python that has the model packages installed. Set SCREENPILOT_LOCAL_DEVICE to auto (default), cuda, cpu or mps to choose where the model runs.

Check the result:

screenpilot voices --provider local
screenpilot doctor

voices --provider local lists the installed models and their voices. doctor has a "local voice" check. It is skipped when you have not set up a local voice, because local voices are optional.

Use a local voice#

Set the provider and the name in the storyboard:

"voice": { "provider": "local", "name": "voicetut:Sarah", "rate": "+0%" }

For a local provider, name is one of:

  • voicetut: the default voice of that model.
  • voicetut:<Voice>: one of its voices, for example voicetut:Sarah.
  • namaa: the only NAMAA voice.

The language of each line is detected for you. A line with Arabic letters is Arabic. Any other line is English. rate (for example +10%) becomes a speed factor for VoiceTut. NAMAA ignores it.

To start a storyboard with a local voice:

screenpilot init sessions/2026-10-27_14-02 --provider local --voice voicetut:Sarah

The MCP tools voices and storyboard_init take a provider argument too, and so does the voice object in a take.json.

Mix models in one video#

A narration line can set its own voice. It replaces the name and keeps the provider. So you can speak Arabic lines with NAMAA and English lines with VoiceTut:

"voice": { "provider": "local", "name": "voicetut:Sarah" },
"narration": [
  { "at": 1, "text": "Invoices can now repeat on a schedule." },
  { "at": 6, "text": "ويمكنك إيقافها في أي وقت.", "voice": "namaa" }
]

Tips#

  • Keep lines short. A long line freezes the video to make room.
  • Generated clips are cached, so rendering again is fast. Only lines you change are spoken again.
  • Listen to Arabic lines before you deliver, and check any numbers.

Limits and measured numbers#

These numbers were measured on one machine: an NVIDIA RTX 2050 with 4 GB of memory.

ModelPeak GPU memorySpeed

  • On a CPU it is much slower. This was not measured.
  • Arabic is less accurate than English. NAMAA can miss the "ق" sound and misread numbers.

Audio from a website#

The built-in voices are free, but a web text-to-speech service can sound better. You can make the audio there and put it on the video: screenpilot writes the script, you generate the voice, and screenpilot lays it on the picture.

  1. Write the narration in the storyboard as usual, then run screenpilot script storyboard.json. It writes storyboard.script.md with the text to paste (one paragraph per line, a blank line between them) and a short prompt for the site.
  2. Paste the text into the site and generate one audio file. Many free plans limit characters or requests per day, so one file for the whole script is the safest. Download it.
  3. Run screenpilot split-audio voice.mp3 --storyboard storyboard.json. It cuts the file at the pauses into one clip per line and sets audio on each narration line.
  4. Render as usual. A line with audio plays its file instead of a voice, and the video still freezes when a line is longer than its room.

Prefer one file per line? Download each line and set narration[].audio yourself, a path relative to the storyboard. text stays as the subtitle.

Check the terms of the site before you publish. Free plans are often limited to personal use, or require a credit to the service. Their limits change, so read the current pricing page.

If split-audio says it found too few pauses, generate the audio again with a clearer pause between lines, or pass a smaller --min-silence. If it warns that two pauses are almost as long, listen to the clips: a long pause inside a line can be mistaken for a line break.

Your own model#

A command voice runs a program of your choice. The program receives the text and writes an audio file. Piper, Kokoro or a script that calls a model you trust all work.

Define the voice in voices.json, in the config folder:

  • Linux and macOS: ~/.config/screenpilot/voices.json
  • Windows: %APPDATA%\screenpilot\voices.json

Set SCREENPILOT_VOICES_FILE to use another path. This file is yours. It lives outside the storyboard on purpose: a storyboard from an AI or from someone else must never be able to run programs.

The fields#

{
  "commands": {
    "my-voice": {
      "command": ["program", "arg", "{out}"],
      "stdin": "{text}",
      "ext": "wav",
      "timeout": 120,
      "env": {}
    }
  }
}
FieldMeaning
commandThe program and its arguments. No shell is used, so the text cannot inject commands. A leading ~/ in an argument means your home folder.
stdinOptional. Text piped to the program, usually {text}.
extExtension of the file the program writes. Default wav. Any format ffmpeg reads works.
timeoutSeconds allowed for one line. Default 120.
envOptional. Extra environment variables for the program.
cacheFilesOptional. Files the program reads, such as pre-made clips. Generated lines are cached by command and text; when one of these files changes (size or modified time), the lines are made again. A missing file counts as a state of its own. A leading ~/ means your home folder.

The placeholders you can use in command and stdin:

PlaceholderReplaced with
{text}The narration line.
{rate}The voice rate, for example +10%.
{speed}The rate as a speed factor, for example 1.1.
{lang}ar for a line with Arabic letters, otherwise en.
{out}The path the program must write the audio to.

The program must write the audio to {out}.

Example: Piper#

This example shows the shape of the file. It was not run here, so check the paths and flags against your Piper install.

{
  "commands": {
    "piper-amy": {
      "command": ["piper", "--model", "~/models/en_US-amy-medium.onnx", "--output_file", "{out}"],
      "stdin": "{text}"
    }
  }
}

Then use it in the storyboard. The name is the key you defined:

"voice": { "provider": "command", "name": "piper-amy" }

screenpilot voices --provider command lists the voices defined in your voices.json.

Wrap any model in a script#

If a model has no command line, write a small script of your own and point command at it:

{
  "commands": {
    "my-model": {
      "command": ["python3", "~/tts/say.py", "{lang}", "{out}"],
      "stdin": "{text}",
      "timeout": 300
    }
  }
}

The script ~/tts/say.py is yours. It reads the text from stdin, reads the language from its first argument, and writes the audio file to the path in its second argument. Raise timeout for a slow model.

Troubleshooting#

You seeWhat to do
No local voice engine is set up, and it says to run voice-setup.Run screenpilot voice-setup voicetut. Or set SCREENPILOT_LOCAL_PYTHON to a Python that has a model installed.
The GPU ran out of memory. The message suggests SCREENPILOT_LOCAL_DEVICE=cpu.Set SCREENPILOT_LOCAL_DEVICE=cpu. It is slower. Or use voicetut, which needs less GPU memory than namaa.
A line on stderr: ignoring unknown setting "..." (written by a newer version?).voices.json has a setting this version does not know, for example one added by a newer ScreenPilot. It is ignored and everything else still works. Update ScreenPilot to use it. A real mistake (wrong type, empty command) still stops with the path and the problem.
An unknown local voice, with a list of the valid models.Use voicetut, voicetut:<Voice> or namaa. List what is installed with screenpilot voices --provider local.
A command voice finished but wrote no audio, and the message names voices.json.Check that the program writes its audio to {out} and that ext matches the file it writes. Run the program by hand with a real path.
The voice engine stopped, followed by its last lines of output.Read those lines: they are what the engine printed before it stopped. Run screenpilot doctor and read the "local voice" check.
voice-setup says it needs uv.Install uv and run the command again.
voice-setup says there is not enough disk space.Free space, or pass --dir to use another drive.
ELEVENLABS_API_KEY or GEMINI_API_KEY is not set.Export the variable, or run screenpilot secret set elevenlabs or screenpilot secret set gemini and paste the key. Check with screenpilot secret status.
ElevenLabs answered 401 invalid_api_key and says the key is for a data residency stack.The key belongs to a region. Run screenpilot endpoint set elevenlabs eu (or in, sg), then screenpilot doctor. See Region and base URL.
A cloud voice answered 401 or 403.The key is wrong or has no access. Set it again. An environment variable wins over a stored key, so check secret status. If you use a gateway or another region, check the base URL (screenpilot endpoint status).
A cloud voice says the reply is not audio (or not JSON), with a content type such as text/html.The base URL points at a web page or login screen, not at the API. Check screenpilot endpoint status.
A cloud voice answered 429.You hit the limit of your plan. ScreenPilot tries 3 times, then stops. Wait, or change plan or provider. Lines already made are cached.
ElevenLabs has no voice with that name on this account.Use a voice id, or one of the names the message lists. Run screenpilot voices --provider elevenlabs.
More answers are on the FAQ. The command line is in voice-setup and voices.
