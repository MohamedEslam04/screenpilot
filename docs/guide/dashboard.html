Dashboard

A small native window for your recordings, renders, running jobs and voices. What it shows, what it does, how to start it, and how to build it for now.

The dashboard is a separate small desktop program. It shows everything ScreenPilot recorded and rendered, the renders running now, your voice providers and some numbers about your renders. It runs on your computer only and does not need an account. It is a native program written in Rust with Slint and the software renderer. It has no web view.

The dashboard is new. Releases newer than 0.10.0 include it. If you have 0.10.0 or an older release, you have to build it from the repository: see Build it from source. The Windows and macOS builds are checked automatically on GitHub's runners (CI), but the maintainer has not run them on real desktops. It has been run on Linux with Wayland. Expect rough edges.

Start the dashboard#

Every release package includes the dashboard, in a dashboard folder next to dist: the Windows installer and zip, the Linux tar.gz and both macOS zips (Apple Silicon and Intel). The Claude Desktop .mcpb files do not contain it. screenpilot setup runs when you install, and it adds the dashboard to the places where your system looks for apps. See The app entry on each system. screenpilot update replaces the dashboard along with the rest of the app.

To start it from a terminal, run:

screenpilot dashboard

It starts the program and returns at once. The dashboard is its own program with its own window. The window and the Dock or task bar show the ScreenPilot logo.

ScreenPilot looks for the program in this order:

  1. The path in the SCREENPILOT_DASHBOARD_BIN environment variable, if you set it.
  2. The dashboard folder in the installed app.
  3. The dashboard folder in the folder you ran setup from.
  4. The dashboard folder of a build from source: the app folder with -dashboard added to its name, next to it.

The program is named screenpilot-dashboard (screenpilot-dashboard.exe on Windows). The folder of a build from source is:

  • Linux: ~/.local/share/screenpilot-dashboard
  • Windows: %LOCALAPPDATA%\ScreenPilot-dashboard
  • macOS: ~/Library/Application Support/ScreenPilot-dashboard

If the program is not found, screenpilot dashboard says it is not installed.

The app entry on each system#

screenpilot setup adds the dashboard where each system looks for apps, with the ScreenPilot logo. The installer, install.sh and Install ScreenPilot.command all run it.

SystemWhere it appears
WindowsA Start Menu shortcut named ScreenPilot Dashboard. The logo is inside the program, which needs no Visual C++ redistributable and opens no console window.
macOSThe app ~/Applications/ScreenPilot Dashboard.app, in Finder and Launchpad. Its icon is made from the logo with the system tools sips and iconutil.
LinuxAn application menu entry, ~/.local/share/applications/screenpilot-dashboard.desktop. The logo is copied to ~/.local/share/icons/hicolor/512x512/apps/.

screenpilot setup --remove and the uninstallers take the entry away.

On macOS the download is not signed or notarized, like the rest of ScreenPilot. Install ScreenPilot.command clears the quarantine flag of the whole folder, so the dashboard opens. If macOS still asks, open System Settings, then Privacy & Security, and click Open Anyway.

Build it from source#

You only need this for 0.10.0 or an older release, or to work on the dashboard. You need Rust. On Linux you also need the development packages for fontconfig, freetype, xkbcommon, Wayland and X11. On Fedora:

sudo dnf install fontconfig-devel freetype-devel libxkbcommon-devel wayland-devel libX11-devel libxcb-devel

Then build the program from the repository:

cd dashboard
cargo build --release -p screenpilot-dashboard

Put the program it builds (screenpilot-dashboard, in target/release) in the folder listed under Start the dashboard for a build from source, or point SCREENPILOT_DASHBOARD_BIN at it.

What it shows#

The window has four tabs: Library, Live, Voices and Stats.

Library#

The Library lists your recordings, takes, renders and sequences from history.jsonl, newest first. It loads 50 rows at a time, and Load older adds more. The search box searches the loaded rows. The buttons above the list filter by kind (Records, Takes, Renders, Sequences) or show only failed work.

Select a row to open the detail panel:

  • A thumbnail of the video, when the work has one.
  • A summary: kind, time, status, duration, quality, how long it took, and the paths. A failed job shows its error. For a storyboard it adds the output size, voice and source, and how many narration lines, captions, zooms, highlights and segments it has. A sequence lists its parts.
  • The narration lines with their times.
  • The files in the folder, with their sizes.
Times in the detail panel are UTC. The history stores UTC, and the dashboard does not convert it to your time zone.

Live#

The Live tab lists the renders running now, with the quality, the time elapsed and a progress bar when the render knows its step (chunk 3 of 12, or part 2 of 4). It updates when a render moves to its next step. A number on the tab shows how many are running. It lists renders started from anywhere: the dashboard, the command line or your AI app.

Voices#

The Voices tab shows one card for each provider: edge, local, command, elevenlabs and gemini. Each card says where the narration text goes and, for ElevenLabs and Gemini, whether a key is set: set by an environment variable, saved, or no key. For those two you can paste a key into a password field and press Save key, or press Remove key to delete a saved key. A card also shows the screenpilot secret set line to run from a terminal instead. A note at the top reminds you that online voices receive your narration text. Voices explains the providers.

The window does not list the voices of a provider. Run screenpilot voices --provider <id> in a terminal for that. See voices.

Stats#

The Stats tab shows how many events the history holds, the render speed for each quality (video seconds made per second of waiting, from your finished renders, with the number of runs), and the size of the render cache. The cache is measured only when you press Calculate (it becomes Recalculate afterwards), because a large cache can take a while. At the bottom is a "Built with Slint" line. Slint's royalty-free licence requires it.

What you can do#

These buttons are in the detail panel of a row:

ButtonWhat it does
Open videoOpens the video with your operating system's default player. The window has no video player of its own.
Show in folderOpens the folder that holds the video or the session.
Render draftRuns screenpilot render on the storyboard with -q draft. It starts in the background. Follow it on the Live tab.
Render deliveryThe same at delivery quality. You click twice: the button first changes to Confirm delivery render.

The render buttons appear for a render and for a take that wrote a storyboard. A sequence has none.

The panel also has a Command box with the command to run the same job in a terminal: screenpilot render, or screenpilot sequence for a sequence. The window has no clipboard access, so the box is selectable text. Press Select all, then Ctrl+C.

The dashboard opens only videos, images, subtitles, audio and text files. It refuses to open anything else, such as a program or a script. Show in folder works for any file, because it only shows it in its folder.

Keyboard#

In the Library you can work without the mouse:

KeyWhat it does
Up and Down arrowsMove through the list.
Page Up and Page DownMove a page at a time.
Home and EndJump to the first or the last loaded row.
EnterOpen the detail panel of the selected row.
/Go to the Library and focus the search box.
EscClear the search. If it is already empty, close the detail panel.

Theme and language#

  • The theme follows your system's light or dark setting. The button in the header switches it by hand.
  • Arabic text is drawn right to left with joined letters. The program carries its own Noto Sans and Noto Sans Arabic fonts, so no Arabic font needs to be installed on your system.

Work from before the history#

The Library reads history.jsonl. Recordings and renders you made before the history existed are not in it. Add them from a terminal:

screenpilot library import

See library for the folders it looks in.

How keys are stored#

When you save a key on the Voices tab, the dashboard does not keep it. It sends the key to screenpilot secret set on standard input, and ScreenPilot writes it to secrets.json in the config folder with file mode 0600. The dashboard never shows a key again, and it never reads secrets.json. A key set by an environment variable cannot be changed or removed there. secret has the same commands for the terminal.

Why it stays light#

  • It is small. With 2,000 history rows loaded, it uses about 14 MB of memory. A version built on a web view measured 330 MB here, which is why the dashboard is native.
  • No background process. Closing the window ends the program, so it uses nothing while closed.
  • No CPU when idle, and no polling. It watches the folder of running jobs only while the window is shown. A one-second clock runs only while the Live tab shows running jobs.
  • The list draws only the rows you can see, and loads older rows when you ask.
  • A thumbnail is made once, by ffmpeg, when you select a video. It is saved in the thumbs folder of the cache folder and reused.
  • Slow work, such as starting a render or reading a project, runs on worker threads, so the window stays responsive.

Local only#

The dashboard window makes no network requests. It reads files on your computer and runs the screenpilot command to start renders and store keys.

More commands are in the command line page: history, library and secret.
